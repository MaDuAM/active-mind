# ActiveMind

## A Full-Stack Project with Depth

ActiveMind is a personal knowledge and action management system – built to tame the growing flood of information, strategies, and insights generated by daily AI use. It is also a demonstration of my ability to design, architect, and deliver a production-ready full-stack application.

**Live Repository:** [github.com/MaDuAM/active-mind](https://github.com/MaDuAM/active-mind)

---

## What It Does

ActiveMind organizes information into three distinct entry types:

| Type | Purpose |
| :--- | :--- |
| **Knowledge** | Static information, reference material, and insights |
| **Passive** | Trackable actions with status (WAITING, ACTIVE, PAUSED) |
| **Active** | Step-by-step processes with progress tracking |

**Additional features:**
- Full-text search with suggestions and result layering
- Status change history and tracking logs
- Soft delete with trash restore
- Infinite scroll with pagination
- Dark mode (system-aware)
- Responsive design (desktop, tablet, mobile)

## How I Built It – And What I Learned

I built this project in close collaboration with AI (ChatGPT). But this was not a simple "copy-paste" process. It was a journey of trial, error, and systematic improvement.

**The First Attempt (Failed):** I started with enthusiasm, but without a clear plan. The AI praised every idea, pushed me to code immediately, and optimized parts of the app to enterprise level while other parts remained incomplete. When I tried to fix it, I realized: I had lost control. The app broke, and without Git, there was no way back.

**The Turning Point:** I stopped. I analyzed what went wrong and developed a new system:
- **Plan first, code second:** I refused to write a single line of code until the functional specification was complete.
- **Precise changes, not full files:** Instead of regenerating entire files, I forced the AI to provide exact line changes with context.
- **Options, not answers:** I stopped asking "What is the solution?" and started asking "What are the options, and what are their trade-offs?"
- **Critical questioning:** Every AI suggestion was challenged. If I couldn't explain why a solution worked, I rejected it.

**The Result:** ActiveMind was built in 4 weeks – with full control, clear architecture, and no overengineering. The AI became my partner, not my substitute.

**The Key Insight:** AI is an excellent assistant, but a terrible leader. It praises too quickly, pushes too fast, and optimizes too early. The human's role is to define the vision, make the decisions, and critically question every AI suggestion.

## Code Quality & Architecture

Backend Structure:
- entries.ts split into route-based modules (routes/entries/)
- Each HTTP method in its own file (get.ts, post.ts, put.ts, delete.ts, status.ts, step.ts, tracking.ts)
- Clean separation of concerns – easier to test and maintain

Frontend Optimizations:
- LoadingOverlay component with backdrop blur for consistent UX
- useLoadingDebounce hook to prevent overlay flicker on fast loads
- useSectionState hook with auto-expand only once (prevents overriding manual user toggles)
- queryClient.clear() on auth actions to prevent cross-user data leaks

What I Would Do Differently Next Time
- Start with a clearer API contract (OpenAPI/Swagger) before implementing
- Add end-to-end tests earlier in the process
- Use feature flags for faster iteration on experimental UI changes
- Set up CI/CD from day one
